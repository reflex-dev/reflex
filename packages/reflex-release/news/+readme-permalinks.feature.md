The publish workflow now rewrites the README's relative links into permalinks before building, so a description on PyPI — where relative links resolve against `pypi.org` and 404 — links to the files as they were in the version being published: `docs/guide.md` becomes `https://github.com/OWNER/REPO/blob/<sha>/docs/guide.md`, images become raw URLs, and a `#heading` link points at the README on GitHub, where the anchor exists. Only targets that are present in the checkout are rewritten, in the build tree and never in a commit, so the README stays written for GitHub. Adopters get the new `rewrite-readme-links` step by re-running `reflex-release sync`.
