Operations on an optional string var (`str | None`) holding `None` no longer crash the page or the production prerender: the string acts as an empty string, so `lower`, `strip` and `replace` give an empty string, `contains`, `startswith` and `endswith` are false and `split(" ")` gives `[""]`. Before, the operations compiled to a native string method (`split` with a separator, `strip`, `lower`, `upper`, `contains`, ...) threw `Cannot read properties of null`, while `length`, indexing and slicing already read `None` as empty.
