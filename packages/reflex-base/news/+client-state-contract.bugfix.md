Tighten the `rx.client_state` contract. A `name` must be an ASCII identifier without `$` (letters, digits and underscores), and the error names the bad value. Declaring one name with two different defaults now fails the compile with both declaration sites instead of letting the first mounted one win, while identical declarations stay allowed. Names that differ only in case (`item`/`Item`) no longer break the build with a duplicate setter. The error for `push`/`retrieve`/`global_value`/`global_set` on an unnamed var now shows the right call, `rx.client_state(default, name="my_name")`, and points out a default that looks like a misplaced name. Compiled setters are now named `<name>RxClientStateSet` instead of `set<Name>`.
