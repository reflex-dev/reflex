Fix a runaway `on_load` chain when an event reaches expired state without any routing data, as one enqueued from the backend does. The compatibility rehydrate ran the loaders for the empty route (the 404 ones) and left `router_data` unset, so every event it chained rehydrated in turn and the chain fanned out without end. Such an event now hydrates the state and marks it hydrated without running page loaders, once rather than per event, and the first event that does carry a route still gets its page's `on_load`.
