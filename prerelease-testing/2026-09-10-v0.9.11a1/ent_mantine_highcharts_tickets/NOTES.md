## ISSUE 1 (HIGH, pre-existing, framework half + reflex-enterprise half) — the tickets demo's UI never dispatches a single event

The demo that exists to show off `EventHandlerAPIPlugin` cannot be used in a browser at all. Seed,
New Ticket, Apply, Reset filters, sort, Start/Close, Delete, Clear all: every control is inert, in
**dev and in prod**, on **0.9.11a1 and 0.9.10.post2**. The REST API of the very same app works
fine, so the backend is healthy — nothing ever leaves the browser.

Mechanism, end to end:

1. `rxe.EventHandlerAPIPlugin` imports `reflex_enterprise.auth.enforcement`, which imports
   `reflex_enterprise/auth/oidc/state.py`, which *defines* `GenericOIDCAuthState` and
   `IsIframedState` as `rx.State` subclasses. They join the backend state tree even though the app
   configures no auth plugin and renders no auth component.
2. The hydrate delta therefore carries 8 substates
   (`scripts/probe_delta_keys.py`, `out/tickets_delta_keys_prod.json`):
   ```
   reflex___state____state
   ...reflex___state____on_load_internal_state
   ...reflex___istate___shared____shared_state_base_internal
   ...reflex_enterprise___auth___oidc___state____generic_oidc_auth_state   <-- no dispatcher
   ...reflex_enterprise___auth___oidc___state____is_iframed_state          <-- no dispatcher
   ...reflex___state____update_vars_internal_state
   ...reflex___state____frontend_event_exception_state
   ...tickets___tickets____ticket_state
   ```
3. The compiled page has dispatch functions for every substate it renders (framework internals
   included) but not for the two enterprise auth ones, so `.web/utils/state.js` takes its
   "fatal mismatch" branch: it logs `Cannot process state update: no dispatch function for
   substate(s) ...`, emits a `client_error`, and sets `backend_state_mismatch = true`.
4. That flag is a one-way latch. `processEvent()` then starts with
   ```js
   // A backend/frontend state mismatch is fatal; do not send further events.
   if (backend_state_mismatch) { event_queue.length = 0; return; }
   ```
   so from the first hydrate onwards every user event is discarded client-side. Verified with
   socket capture: clicking **Seed** produces **zero** sent frames
   (`scripts/probe_tickets_hydrate.py`, `out/tickets_hydrate_a1.json`).
5. The error text tells the user to refresh the page or rebuild the frontend. Neither helps — the
   condition is deterministic on every load.

Repro from scratch (no QA modules needed):

```bash
cd $A/tickets && CI=true REFLEX_TELEMETRY_ENABLED=false \
  $SB/envs/mht_a1/bin/reflex run --frontend-port 5422 --backend-port 9822
cd $A && NO_PROXY=localhost,127.0.0.1 no_proxy=localhost,127.0.0.1 \
  $SB/envs/driver/bin/python scripts/probe_tickets_hydrate.py http://localhost:5422/
# --- after clicking Seed: new sent frames 0
# --- rows now: 0 | badges: ['Open: 0', 'Total: 0']
# the row count in tickets.db is unchanged afterwards (0 on a fresh DB): the handler never ran
```

Baseline: byte-for-byte the same behaviour on 0.9.10.post2
(`out/tickets_hydrate_base.json`, `logs/tickets_dev_base.trimmed.log`) — the latch code is
identical in both `.web/utils/state.js`. **Not a regression of this train**, but the impact is much
larger than pass 1's FINDING-036 ("two console errors, nothing visibly breaks") recorded, and
FINDING-036 should be re-rated.

Confirmation of the mechanism and the workaround: `QA_REF=1` adds `/ref`, which renders
`IsIframedState.is_iframed` and `GenericOIDCAuthState.user_error_message` above the very same
`index()` UI. On `/ref` the page hydrates with no error, `Seed` sends its event and 4 rows appear
(`out/tickets_hydrate_qaref.json`, `shots/tickets_ref_a1/`). So "render at least one var from every
substate the backend knows about" is the user-side workaround. In **prod** the dispatch map is
per-bundle, so the presence of `/ref` anywhere in the app revived `/` as well — which is why the
prod check had to be repeated with `QA_REF` unset before concluding
(`out/tickets_hydrate_prod_noref.json`: dead again).

Two fixes are plausible and independent: reflex should not treat a delta for a substate the page
does not use as fatal (or should not send it), and reflex-enterprise should not register auth
states in apps that configure no auth provider.

## ISSUE 2 (LOW, pre-existing, reflex-enterprise) — `/_reflex/events/openapi.yaml` returns 500

Re-confirmation of FINDING-035 with independent venvs: `GET /_reflex/events/openapi.yaml` is 500 on
0.9.11a1 **and** 0.9.10.post2 because starlette's schema generator needs PyYAML and nothing in the
dependency chain declares it. `/.well-known/api-catalog` advertises that exact URL, so the
documented entry point of the plugin is broken out of the box. `pip install pyyaml` fixes it (pass 1
saved the resulting 27 KB document as `out/tickets_openapi_with_pyyaml.yaml`).

## ISSUE 3 (LOW, pre-existing, reflex) — every decorated page logs "is being redefined" in prod

`reflex run --env prod` logs, once per `@rx.page`-decorated page, after `App Running`:

```
Warning: Page dates is being redefined with the same component.
Warning: Page pill is being redefined with the same component.
Warning: Page tags-input is being redefined with the same component.
Warning: Page index is being redefined with the same component.
```

`compile_app()` calls `app._apply_decorated_pages()` (compiler.py:1170) and the decorated pages live
on the `RegistrationContext`, which is only cleared on a `get_app(reload=True)`; in the prod worker
the pages are applied twice, and `_register_prepared_page()` (app.py:1082) warns for each. Dev logs
zero such warnings. Pristine mantine demo, 4 pages → 4 warnings, on **both** versions
(`logs/mantine_prod_a1.trimmed.log`, `logs/mantine_prod_base.trimmed.log`). Harmless but it looks
like the user double-registered their pages.

## ISSUE 4 (MEDIUM for QA, pre-existing, reflex-enterprise) — enterprise prod mode is unreachable without a paid licence, and the refusal is preceded by a framework DeprecationWarning

`reflex_enterprise.utils.check_paid_tier_for_command()` refuses both `reflex export` and
`reflex run --env prod` for anonymous/free tiers. `CI=true`, which bypasses the *login* gate in
`AppEnterprise._check_login()`, does **not** bypass this one, so the previous campaign's conclusion
("no way to exercise enterprise prod mode") holds for the documented knobs. Full output:
`logs/ent_prod_paid_gate_a1.log`:

```
DeprecationWarning: console.error has been deprecated in version 0.9.9. use
logger.error(msg) on logging.getLogger(__name__) instead. It will be completely
removed in 1.0.
(.../site-packages/reflex_enterprise/utils.py:119)
`reflex run --env prod` requires a paid Reflex subscription (one of pro, team,
enterprise). You are currently logged out. ...
```

Two things worth acting on: (a) a paid-tier refusal that prints a *framework deprecation warning*
first reads like a bug in the user's app — this is 2026-08-27 FINDING-029, still unfixed: rxe 0.9.5
calls the deprecated `console.error`/`console.info` at `app.py:120`, `utils.py:119`, `proxy.py:135`
and `plugins/mcp.py:1037`, and `console.error` is still deprecated in reflex-base 0.9.11a1
(`out/probe_legacy_a1.txt`); (b) there is no supported QA/CI escape hatch. The one that works is
reflex's own app-harness flag, which `check_paid_tier_for_command()` returns early for:

```bash
APP_HARNESS_FLAG=1 CI=true reflex run --env prod --frontend-port 5430 --backend-port 5430
```

All prod runs in this cluster used it. Its only side effect is `TEST_MODE=true` in the vite build
env (`reflex/utils/build.py:25`); every prod result above was cross-checked against the dev run of
the same route and matched.

## ISSUE 5 (LOW, pre-existing, reflex-enterprise) — the event-handler REST API answers 200 for failed calls

`POST /_reflex/event/<state>/<handler>` returns **HTTP 200** with an error body when the call is
invalid, so a client that checks the status code cannot tell success from failure
(`out/tickets_api_a1.json`):

```
create_ticket  {}                          -> 200 {"error": "Error processing event: TicketState.create_ticket() missing 1 required positional argument: 'title'. ..."}
create_ticket  {"title": 12345, ...}       -> 200 {"error": "Error processing event: 'int' object has no attribute 'strip'. ..."}
```

Authentication failures (401) and unknown handlers/states (404) *are* correct, so only the
handler-invocation path is affected. Payload types are not validated against the handler signature
before the call, which is why a wrong type surfaces as an internal `AttributeError` string.

## ISSUE 6 (LOW, pre-existing, downstream/Highcharts) — the first click on a chart point is swallowed

On a freshly loaded highcharts page the first click on a `.highcharts-point` produces no websocket
frame at all; the second click on the same point works, and so does the first click if a
`mouse-move`/hover reaches the point first (`scripts/probe_firstclick.py`):

```
attempt 1 (hover_first=False): text unchanged,          new sent frames: []
attempt 2 (hover_first=False): "Clicked Mar: 3 units",  new sent frames: [on_point_click ...]
attempt 1 (hover_first=True):  "Clicked Mar: 3 units",  new sent frames: [on_point_click ...]
```

Identical on 0.9.10.post2. Real users move the pointer before clicking, so the practical impact is
on test automation (a Playwright `click()` on a chart point needs a preceding `hover()`), but it is
worth a line in the highcharts docs.

## Benign-but-surprising observations (no action expected)

* Highcharts logs `Highcharts warning: Consider including the "accessibility.js" module ...` as a
  `console.warn` on every chart render, forwarded into the server log by vite. Expected for a build
  without the a11y module.
* State survives F5 in dev: `state_manager_mode=DISK` is the default, and the client token lives in
  `sessionStorage`, so reloading a page restores the previous state (my first driver script wrongly
  expected a reset). `/tags-input` and the highcharts click text both demonstrate it.
* In prod, `reflex_enterprise/plugins/api_tokens.py:114` logs `Using the in-memory API token store
  (no Redis configured). Tokens do not survive restarts and are per-process; configure redis_url for
  multi-worker deployments.` — via the deprecated `console.debug`, so it too is preceded by a
  DeprecationWarning.
* `reflex db init` prints `Warning: Database is not initialized, run reflex db init first.` *while
  running* `reflex db init`.
* The tickets demo builds on `rx.Model`, deprecated since 0.9.2 (removal 1.0); every DB command and
  every server start prints two such warnings.
* `Debug: Unable to bind to any port for 10: [Errno 97] Address family not supported by protocol` on
  every start — this container has no IPv6.
* Mantine's `/dates` renders 12 date components, 156 buttons and 387 `mantine-*` elements on one
  page and still hydrates in well under a second; no perf cliff observed.
* Only `/`, `/dates`, `/pill` and `/tags-input` are registered by the mantine demo — the
  `route="/accordion"` etc. values in the other `*_demo.py` modules are dead because
  `mantine/mantine.py` keeps their imports commented out upstream.
* Driver pitfall worth remembering: Playwright's `text=Example` matches *substrings*
  case-insensitively, so it hit the page description paragraph instead of the `Example` tab and made
  a working tab round trip look broken. `[role=tab]` nth selectors fixed it
  (`out/mantine_tabs_a1.json` is the clean run).

### Mechanism, narrowed and named (file:line)

The compiled frontend's dispatch map is a **compile-time snapshot of the state tree**, and reflex
runs plugin `post_compile` hooks **after** that snapshot is taken:

1. `reflex/app.py:757` `self._compile(...)` → `reflex/compiler/compiler.py:1404`
   `compile_contexts(app._state, ...)` → `reflex/compiler/utils.py:221`
   `state(_reflex_internal_init=True).dict(initial=True)`. The resulting `initialState` keys are
   the *only* dispatchers emitted into `.web/utils/context.jsx`
   (`packages/reflex-base/src/reflex_base/compiler/templates.py:482` `StateProvider`).
2. `reflex/app.py:779` `plugin.post_compile(app=self)` runs next, i.e. **after** the snapshot.
3. rxe 0.9.5: `plugins/event_handler_api.py:1486 post_compile` → `:596 collect_page_info` →
   `:305 _is_public_handler` → `auth/enforcement.py:947 is_exempt` →
   `from reflex_enterprise.auth.oidc.state import OIDCAuthState`, which executes
   `auth/oidc/state.py` and *defines* `IsIframedState` (`:212`) and `GenericOIDCAuthState`
   (`:2776`) as `rx.State` subclasses. Traced with an import hook:
   `verification/scripts/probe_import_origin.py`.
4. Proof of the ordering, with no browser involved (`verification/scripts/probe_state_tree_order.py`,
   `probe_registry.py`, `probe_compile_state.py`):
   ```
   after get_app  substates: 5  (no oidc)      <- what context.jsx is generated from
   after app()    substates: 7  (+ generic_oidc_auth_state, is_iframed_state)
   compile_state(app._state) keys: 6  (root + 5)
   ```
5. The runtime hydrate delta therefore contains 8 substates, 2 of which have no dispatcher.
   `packages/reflex-base/src/reflex_base/.templates/web/utils/state.js:734-751` logs the error,
   emits `client_error`, and sets `backend_state_mismatch = true`; `:725` then drops every
   later delta and `:532-535` (`processEvent`) clears and refuses the event queue for the
   lifetime of the page. One-way latch, hit on the very first delta of every load.
6. "Try refreshing the page ... rebuild the frontend" cannot work: every compile re-takes the
   snapshot before `post_compile`, so the mismatch is deterministic.

### Severity / scope judgment

* **high**, but **not a release blocker for 0.9.11**: byte-identical on 0.9.10.post2, so nothing in
  this train caused or worsened it. Recording it as pre-existing high (it makes an advertised
  enterprise plugin unusable in a browser) matches what pass 2 said; pass 1's FINDING-036
  ("nothing visibly breaks") is definitely mis-rated.
* **downstream = true** and broader than the demo: any app with
  `rxe.Config(plugins=[rxe.EventHandlerAPIPlugin()])` and no auth provider is completely inert in
  the browser. `rxe.MCPPlugin` and `rxe.AuthPlugin` also implement `post_compile`
  (`plugins/mcp.py:1747`, `plugins/auth.py:319`) and are worth the same check; an app that
  configures auth normally imports the OIDC state module itself at module import time, which is
  why auth apps are unaffected.
* Two independent fixes, as the claim says. Framework side, the cheapest correct one is to take
  the `compile_contexts` snapshot *after* the `post_compile` hooks (or to re-emit `context.jsx`
  when the registry changed during them) and, failing that, to fail loudly server-side at startup
  instead of leaving a browser to discover it and print misleading advice. Enterprise side,
  `is_exempt()` should not need to import the OIDC state module, or the plugin should do its
  auth-related imports in `pre_compile`.
