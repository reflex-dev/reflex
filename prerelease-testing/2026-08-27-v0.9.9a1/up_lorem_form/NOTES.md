# up_lorem_form cluster — upgrade testing 0.9.8 -> 0.9.9a1

Apps from `reflex-dev/reflex-examples`: **lorem-stream** (background/yield-heavy
concurrent streaming; sensitive to #6734/#6920 event-loop changes) and
**form-designer** (reflex[db] + reflex-local-auth 0.5.0: auth/session/sqlite flows).

Verdict: **no regressions found in either app.** The in-place upgrade migration
(lockfile restore, react-router-dom pruning, react-router 7.18.2 -> 8.3.0,
vite 8.0.16 -> 8.2.0) ran cleanly on the first 0.9.9a1 run for both apps, and all
user flows behave identically before/after. form-designer has three pre-existing
app-level breakages that reproduce identically on 0.9.8 stable (NOT regressions).

## Procedure (per app)

1. Copied app from `/home/user/reflex-dev/reflex-examples/<app>` (no .git).
2. `uv venv <app>/venv --python 3.11 && uv pip install --python <app>/venv/bin/python -r requirements.txt 'reflex==0.9.8'`
   (stable resolution; `reflex>=0.9.2` floors resolve to 0.9.8).
3. Ran on 0.9.8 (`--loglevel debug`, log to file), drove all core flows with
   Playwright/Chromium, captured console + failed-request + screenshot baselines,
   saved `.web/package.json`.
4. In-place upgrade of the SAME venv/app dir (`.web/` kept):
   `uv pip install --python <app>/venv/bin/python --prerelease=allow -U 'reflex==0.9.9a1'`.
   Re-ran, watched the first-run migration log, re-drove the same flows, diffed
   `package.json`.
5. Cold run: `rm -rf .web`, run again, re-drove flows.

## Rerun instructions

Servers (one at a time; ports: lorem-stream fp=3220/bp=8220, form-designer fp=3221/bp=8221):

```
cd apps/up_lorem_form/<app>
REFLEX_TELEMETRY_ENABLED=false venv/bin/reflex run --frontend-port <fp> --backend-port <bp> --loglevel debug > logs/run.log 2>&1 &
# poll http://localhost:<fp>/ until 200 (first run does bun install)
```

Drivers (from `apps/up_lorem_form/`, using the shared playwright venv
`$SB/envs/driver/bin/python`, NO_PROXY=localhost,127.0.0.1 on the driver only):

```
python drive_lorem.py <label> http://localhost:3220/
python drive_form_designer.py <label> http://localhost:3221/ full    userX FormX   # register+create+all flows
python drive_form_designer.py <label> http://localhost:3221/ relogin userX FormX   # existing user, form id 1
python probe_disconnect.py http://localhost:3220/    # close browser mid-stream, then read server log
```

`full` mode registers the username, so it needs a fresh `reflex.db` (delete
`reflex.db` + `.states/` with the server stopped) or an unused username.
Results/screenshots/console dumps land in `artifacts/` prefixed by label.
Per-run pass/fail is in `artifacts/<label>_*_results.json`.

Migration observations (logs/099a1_run1.log):
- `Restoring lockfiles` -> creates `reflex.lock/` (bun.lock + package.json) in the
  app root; cold run restores from it and yields a byte-identical `.web/package.json`.
- `bun remove react-router-dom` ("Removed: 1"), then dev/base deps re-added at
  react-router 8.3.0 / vite 8.2.0. During the intermediate `bun add` step bun logs
  `warn: incorrect peer dependency "react-router@7.18.2"` twice — transient, the
  final state is consistent (benign).
- package.json diff (logs/package.json.diff): react-router-dom removed;
  react-router/@react-router/{node,dev,fs-routes} 7.18.2 -> 8.3.0; vite 8.0.16 -> 8.2.0.
- New Debug-level warning on every dev run under 0.9.9a1 (vite 8.2.0):
  "Your Vite config uses features that are unsupported by `configLoader: 'native'`
  ... import './vite-plugin-safari-cachebust' without a file extension
  (vite.config.js:4:35)" — cosmetic today, but that config is generated by reflex
  and will matter when vite flips the default loader.
- Abrupt browser close mid-stream (probe_disconnect.py): background tasks keep
  running and the server logs "Attempting to send delta to disconnected client"
  warnings — byte-for-byte the same behavior as 0.9.8 (also observed there); no
  tracebacks, server stays healthy.
- Prod mode note: `--env prod` with different frontend/backend ports exits with
  "In prod mode, frontend and backend must run on the same port." — same check
  exists in 0.9.8's CLI (verified in the 0.9.8 wheel), NOT a 0.9.9a1 change.

## form-designer

Checks: home page; register; login (auto-redirect + actual auth); create form via
debounced name input; add text field; add radio field with 2 options (nested
options-editor dialog); preview/entry page; submit entry; responses page; logout;
re-login persistence. Upgrade adds: relogin as the 0.9.8-created user against the
0.9.8-created sqlite db.

| run | result |
|---|---|
| 0.9.8 baseline, `full` user098/Form098 | 9/12 PASS; 3 pre-existing failures (below) |
| 0.9.9a1 upgrade, `relogin` user098 | PASS: 0.9.8-created user + form + fields fully usable; same 2 pre-existing entry-page failures |
| 0.9.9a1 upgrade, `full` user099/Form099 | identical to 0.9.8 baseline: 9/12 PASS, same 3 failures |
| 0.9.9a1 cold (`rm -rf .web`), `relogin` user098 | same as upgraded relogin |

Pre-existing failures — reproduce EXACTLY the same on 0.9.8 stable (app-level
version drift in the example, not 0.9.9a1 regressions):
1. **Entry/preview page (`/form/<id>`) crashes into the error boundary**:
   "Error: `FormMessage` must be used within `FormField` or specify the `name`
   prop" (from @radix-ui/react-form 0.1.14; the app's `rx.form.field` wrapper
   passes no `name`). Consequently no entry can be submitted. Screenshots
   `*_fd_entry_page.png`.
2. **Login never auto-redirects away from `/login`** — `LocalAuthState._login`
   authenticates (protected pages render fine afterwards) but
   `LoginState.redir()` does not issue the redirect. Same on both versions.
3. Console errors present on BOTH versions (same set, count 5): 3x "Invalid DOM
   property stroke-linecap/linejoin/width" (rx.logo svg), the FormMessage error
   above, and "Received `true` for a non-boolean attribute `collapsible`"
   (responses page accordion).

Cross-version data continuity (the interesting upgrade result): the sqlite db
(`reflex.db`) written by 0.9.8 (bcrypt local-auth user, Form/Field/Option rows)
is fully usable on 0.9.9a1 — login, form listing, field rendering, logout all
work; `rx.model.migrate()` ran without complaint.

Migration observations: identical shape to lorem-stream (react-router-dom pruned,
router 8.3.0, vite 8.2.0, `reflex.lock/` created; cold-run package.json identical).
No new server-log warnings vs baseline.

### requirements resolution note (reflex[db] extra)

`reflex[db]>=0.9.2` on 0.9.9a1: the db extra = `alembic>=1.15.2`,
`pydantic>=2.12.0,<3.0`, `sqlmodel>=0.0.24` — resolves fine. BUT a **fresh**
install with prereleases enabled (`uv pip install --prerelease=allow` or
`pip install --pre`, which users must use to get 0.9.9a1) also resolves
**pydantic==2.14.0b1 (beta)** because the prerelease flag applies to all
transitive deps. The in-place `-U reflex==0.9.9a1` upgrade keeps pydantic 2.13.4.
The app worked in our (2.13.4) env; the beta-pydantic fresh-install combination is
untested here and is a plausible source of user-reported weirdness during the
alpha period. (Dry-run evidence in NOTES; command:
`uv pip install --dry-run --prerelease=allow -r requirements.txt 'reflex==0.9.9a1'`.)
