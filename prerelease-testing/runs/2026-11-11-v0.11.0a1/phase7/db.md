## NEW-ISSUE-1: kept-env.py failure hint never shows for an alembic.ini with a relative `script_location` (LOW)

- Fix under test: #7809 `report_failure()` adds `CUSTOM_ENV_HINT` and moves the traceback to debug only when
  `_raised_in_env_py()` finds env.py as the innermost frame inside `script_directory()`.
- Defect: `script_directory()` returns `Path(ScriptDirectory.from_config(config).dir)`, which is relative
  (`PosixPath('alembic')`) when alembic.ini says `script_location = alembic`. Traceback filenames are absolute, so
  `path.is_relative_to(scripts)` is never true. The function returns False, the hint is dropped, and the full traceback is
  logged at ERROR. Both reflex-examples apps with a committed alembic dir (form-designer, chat_v2) use the relative form,
  as does any app initialised with an older alembic. `reflex db init` with alembic 1.20 writes `%(here)s/alembic`, which
  works. These long-lived apps are the ones FINDING-005 is about.
- Impact: messaging only. The app still starts and the `reflex db` exit codes are right. The once-per-process "not the
  Reflex template ... Move it aside and run reflex db init" warning still appears just above, so the remedy is visible.
  The user still gets a ~45-line traceback on every `reflex db` command and at startup, which the fix meant to remove.
- Minimal repro (a2 only, no 0.10.1 needed): `bash phase7/db/scripts/hint/relative_script_location.sh $P7/new`
  (fresh app, `reflex db init`, env.py replaced by `raise RuntimeError(...)`):
  ```
  script_location = %(here)s/alembic -> reflex db status rc=1 | hint shown: 1 | traceback lines: 0
  script_location = alembic -> reflex db status rc=1 | hint shown: 0 | traceback lines: 15
  ```
  Real-app evidence: `logs/fd-h1b-cli-a2.head.log`, `logs/fd-h1b-run-a2.excerpt.log`.
- Fix shape: resolve both sides, e.g. `scripts = script_directory().resolve()` and compare
  `Path(path).resolve()`. Alternatively, resolve `script_location` against the alembic.ini directory / cwd in
  `script_directory()`. A relative path also appears in the env.old message (already noted as an a1 anomaly).
