Root cause: `reflex/utils/exec.py` ~726-741 `ParentBoundGranian._init_shared_socket` builds the listening socket in
the granian supervisor (`SocketSpec(...).build()`, `sock.set_inheritable(True)`) so the port stays bound while a
worker is replaced (#7114 — that part works as designed). When no worker is alive (the app module raises at import
after a save; a wedged shutdown) the kernel keeps accepting into the backlog and every request hangs for the client
timeout; 0.9.11.post1, with no supervisor socket, refused instantly. Prod uses plain Granian (`exec.py` ~857).

Fix goal: keep #7114's hot-reload benefit, but while no worker can serve, connections must be refused or answered
promptly (a fast 503 is acceptable), and the socket must be released when the supervisor itself shuts down. Study
granian 2.8.x's supervisor in the worktree venv (`.venv/lib/python*/site-packages/granian/` — worker lifecycle,
respawn loop, how the shared socket is handed to workers) before designing. Candidate shapes: close the listening
socket while zero workers are alive and re-create it for the next spawn (the kernel refuses in between); or bound the
"no live worker" window (stop listening after N seconds without a worker). Prefer the simplest change that the probe
below verifies; avoid busy loops and extra threads unless unavoidable, and explain.

Regression test: the supervisor is hard to unit test; add the most meaningful unit test you can for the new logic
(e.g. the socket is closed when the live-worker count drops to zero / the bound elapses) in
`tests/units/utils/test_exec.py` (create it if missing — the tests tree mirrors the source tree). Must fail before
the fix. The integration-level proof is the probe.
