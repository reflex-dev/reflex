# f012 — FINDING-012 / issue #6143: data_editor overlay portal swallowed by the StickyBadge app-wrap in prod (HIGH impact, pre-existing)

Root cause: `reflex_components_dataeditor/dataeditor.py` registers the Glide portal as the app wrap
`{(-1, "DataEditorPortal"): Portal.create(id="portal")}`. In prod with the default `show_built_with_reflex=True`,
`_setup_sticky_badge` registers `app_wraps[0, "StickyBadge"]` (`reflex/app.py` ~1639-1649; added in prod by
`reflex/compiler/compiler.py` ~1347-1356). `_app_root` (`reflex/app.py` ~1574-1590) sorts wraps by priority descending
and nests each lower-priority wrap as a CHILD of the previous one, so the portal wrap (the only negative-priority
wrap) ends up inside the badge wrap; `StickyBadge.create`
(`packages/reflex-components-core/src/reflex_components_core/core/sticky.py` ~90-107) accepts no `*children` and the
compiled memo never renders `props.children` → `<div id="portal">` never reaches the DOM →
`Cannot open Data Grid overlay editor, because portal not found`. Dev (no badge) works. Pre-existing on 0.9.11.post1,
but 0.9.12a1 ships the image-preview carousel (#7081) that cannot open in prod because of it.

Fix goal: the portal div must reach the DOM in prod with the badge on. Preferred shape: make the StickyBadge app-wrap
render its children (accept `*children` in `create`, pass them through in the compiled component) so ANY
lower-priority app wrap survives — the general fix. Alternative: give the portal a non-negative priority, or have
`_app_root` treat leaf-only wraps specially; explain why you did or did not choose it. If `StickyBadge.create`'s
signature changes, regenerate stubs (`uv run python scripts/make_pyi.py`) and commit `pyi_hashes.json`. News
fragments: `packages/reflex-components-core/news/` (plus `news/` at the root if `reflex/` code changes).

Regression test: a compile-level unit test (in the `tests/units/` mirror of `reflex/app.py` or the compiler) that
builds the app root with a StickyBadge wrap at priority 0 and a lower-priority wrap and asserts the lower-priority
wrap's element appears in the compiled output. Must fail before the fix.

E2E: copy `components_bumps/verification/vapp` to scratch; run
`REFLEX_TELEMETRY_ENABLED=false .venv/bin/reflex run --env prod --frontend-port <fp> --backend-port <fp>` (one port
in prod) from your worktree venv on your ports with the default badge setting; then, with the driver venv, run a copy
of `vdrive.py` / `editor_probe.py` (read them for arguments): `document.getElementById("portal")` must exist, the
badge must still render, and clicking an image cell must open the overlay/carousel with no "portal not found"
console error. Show the same run failing on `envs/shared` (or cite the campaign's `verification/logs` and `shots`).
Prod builds take 3-4 minutes each; plan for two. Save console/network captures and screenshots under
`fixes/f012/evidence/`.
