`RemoteWorkflows(url, token)` starts, reads, lists, signals, waits on, and cancels runs over the `reflex workflows serve` HTTP API — for a FastAPI service, a script, or a partner integration that should hold a scoped API token rather than database credentials. It answers with the same dispositions as in-process code (`deduplicated`, `unknown_run`, `run_terminal`, …), raises on refusals so a missing scope never looks like a run that did not start, and `result(run_id, as_type=Receipt)` validates the wire result back into the declared type exactly as `RunHandle.result` does. `rx.workflows.connect()` remains the client for a process that shares the store.
