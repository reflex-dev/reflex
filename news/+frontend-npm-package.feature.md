The non-generated frontend runtime now ships as a real npm package, `@reflex-dev/reflex-base`, bundled inside the reflex-base wheel as a packed tarball whose version is derived from reflex-base itself. Each run installs it into `.web` like any other dependency (a `file:./<tarball>` entry; editable installs of reflex-base link the live source directory instead, so framework JS edits hot-reload). Compiled code imports it by bare specifier, so the generated output is guaranteed to match the shipped frontend interfaces for the installed version. Upgrading Reflex no longer re-initializes `.web` from scratch: the templates are refreshed in place and the package manager just installs the new tarball, keeping `node_modules` and lockfiles intact.
