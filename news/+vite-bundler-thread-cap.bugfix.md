The dev server now sets `ROLLDOWN_WORKER_THREADS` to the number of CPUs the process may actually use (cgroup CPU quota included), instead of letting rolldown size its worker pool from the host's core count. In containers and sandboxes that advertise many host cores but grant few, the oversized pool retained hundreds of MB of memory that grew with every dependency re-optimization. An explicitly set `ROLLDOWN_WORKER_THREADS` is respected.
