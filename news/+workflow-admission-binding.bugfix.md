Adding a required parameter to a handler now suspends in-flight runs as `NEEDS_ATTENTION` with `incompatible_payload`, naming the parameter to give a default, instead of failing them with a `TypeError` from inside the handler. The HTTP start endpoint accepts a handler's stable `id` as well as its Python method name — the stable id is what runs report, so it has to be what the API takes — and refuses a start whose arguments cannot bind, rather than returning 202 and creating a run that can never succeed.
