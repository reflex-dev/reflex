The prod event websocket now accepts the backend's own origin behind a TLS-terminating proxy that keeps the `Host` header but sends no `X-Forwarded-Proto: https` (for example the `docker-example/production` image on Render or Heroku), and setting `deploy_url` no longer rejects that origin. `X-Forwarded-Host` and `X-Forwarded-Proto` are honored only when `trusted_proxy_hops` is set, and the first rejection in each worker logs a warning naming the setting to change.
