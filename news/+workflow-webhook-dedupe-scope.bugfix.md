Webhook deduplication keys are now namespaced by the root handler they start, so two lifecycle topics served by one workflow no longer collide. A provider numbers its events per object rather than per topic, so `invoice_failed` and `invoice_paid` for one invoice arrive carrying the same id — unqualified, the payment was deduplicated against the failure and silently dropped. Deliveries admitted under the previous unqualified key are still recognised, so upgrading does not make the provider's next redelivery of an already-handled event start it a second time.
