The execution contract's failure matrix now documents the failures that are not crashes — an unregistered workflow, a deleted handler, a payload a handler no longer accepts, a run that blew `max_steps`, a step that exhausted its recovery budget, and an unserializable error payload — each with its stable `reason` and its one outcome. A test walks both directions, so a reason renamed in the engine and not in the contract fails the build instead of silently invalidating a runbook.
