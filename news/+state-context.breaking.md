Each event now checks out its states in its `EventContext`: every lookup during the event gets the same instance of a state, linked into one tree, and taking the state lock refreshes those instances in place and stores the modified ones on release. `StateManager` is now a key-value store of single state instances: a custom state manager implements `load_states`, `store_states` and `lock` instead of `get_state`, `set_state` and `modify_state`, which remain available on every manager. With the in-memory and disk managers, `state_manager.get_state` now returns a tree holding only the states the requested one needs, like the Redis manager; other states load on `get_state`.
