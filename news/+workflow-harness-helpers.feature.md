The test harness drives a run to its end and looks inside it. `WorkflowTestHarness.run_until_terminal(run_id)` advances the virtual clock through every timer and schedule until the run reaches a terminal status — and fails fast, naming the cause, when the run is waiting on a signal or approval the test never sends, instead of spinning to a timeout. `history(run_id)` and `children(run_id)` read the run's event history and the branch runs its joins spawned. `webhook(topic, payload, headers=...)` posts through the real webhook ingress in-process — identity, verification, dedupe, correlation and all — and returns the status and body. `restart()` tears the runtime down and rebuilds it from the store alone, so a test can assert that a run survives a process boundary with nothing but what was durably written.
