A duplicated browser tab now shares the session of the tab it was duplicated from instead of starting an empty one. A `client_token` can have any number of websockets: every one of them, on every backend instance, receives the session's state updates and the frontend events its handlers send (redirects, toasts, downloads). The backend no longer emits `new_token` when a token connects a second time. With Redis, the sockets of a token are stored as a set under `token_manager_sockets_<token>` in place of the `token_manager_socket_record_<token>` record, so instances running the old and the new version do not relay updates to each other during a rolling upgrade.
