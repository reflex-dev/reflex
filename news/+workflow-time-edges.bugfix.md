Two time edges from the production review. Exponential backoff saturates at `max_delay` instead of raising `OverflowError` around attempt 500 — the power ran inside the kernel's completion path, so the overflow would have broken the worker, not the run. And schedule catch-up loss is no longer silent: occurrences beyond `MAX_SCHEDULE_CATCHUP` are skipped with a warning naming the count and window, and the contract's failure matrix now describes what actually happens (the old text claimed a history record that never existed — there is no run to attach one to). The contract also states plainly that a synchronous handler cannot be cancelled by any drain budget: a thread cannot be interrupted, which is the same reason `timeout=` is a compile error on sync handlers.
