`reflex db init` now runs `alembic init` and installs an `alembic/env.py` that loads the app and reads `db_url` from rxconfig.py, and `reflex db migrate`, `makemigrations` and `status` are thin wrappers over `alembic upgrade head`, `alembic revision --autogenerate` and `alembic history --indicate-current`. The `alembic` command line works on the same environment, so `alembic downgrade -1` needs no extra setup, and `alembic revision --autogenerate` and `alembic check` evaluate the pages as `reflex db makemigrations` does, so a model that only a page imports is compared too. In apps initialized by an earlier release, the next `reflex db` command or `migrate()` call replaces the stock `env.py` with the current template, keeping the previous file as `env.old` and the existing revisions; `migrate()` logs a warning when it does so.
