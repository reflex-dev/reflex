### 1d. `reflex[db]` → sqlmodel cap: datetime semantics + migration upgrade path (issue A)

| | 0.10.0a1 + sqlmodel 0.0.44 | 0.9.12 + sqlmodel 0.0.47 |
|---|---|---|
| column type | `DateTime()` | `UTCDateTime()` |
| insert naive `12:00` | ok, read back naive `12:00` | **StatementError** "Datetime values must have timezone information" |
| insert `12:00+00:00` | stored `12:00`, read back **naive** `12:00` | stored `12:00`, read back aware `12:00+00:00` |
| insert `12:00+02:00` | stored **`12:00` (offset dropped)**, read back naive | stored `10:00` (UTC), read back `10:00+00:00` |
| filter with naive value | ok | StatementError |

`logs/1d-dt-probe-*.json`. sqlmodel 0.0.45 was published 2026-09-21T21:51Z, the same day as reflex 0.9.12, so
essentially every fresh 0.9.12 install has the right-hand column. For those users the cap is a behavior *change*:
after upgrading, newly written aware datetimes are stored as wall time instead of UTC. Values come back naive, so
comparisons against aware datetimes raise `TypeError`.
